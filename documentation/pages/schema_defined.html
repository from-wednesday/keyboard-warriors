Shortcut JSON Schema

Field-by-field specification for shortcut entries in the app's JSON files, the fixed chip rendering order, and the JavaScript functions that read this data. See the companion Shortcut Token Reference for the full list of accepted tokens.

01 ) Entry Structure

```

Each shortcut in an app JSON file is an object with the fields below. mac_sc and pc_sc are token strings, built from the tokens listed in the Shortcut Token Reference.

Full entry

{ ``` “display”: “redo”, “mac_sc”: “CMD+SHIFT+Z”, “pc_sc”: “CTRL+SHIFT+Z”, “difficulty”: 2, “group”: “history” }
```

Minimal entry : Mac only, no group

{ ``` “display”: “open keyboard shortcuts”, “mac_sc”: “CONTROL+SHIFT+SLASH”, “pc_sc”: “NULL”, “difficulty”: 3 }

02 ) Field Rules

```
FieldTypeRules
display String Plain text shown as the question. No markup.
mac_sc String Token string for Mac matching and chip rendering. Use the literal value NULL (or NONE) when the shortcut does not exist on Mac. At least one of mac_sc or pc_sc must contain real tokens.
pc_sc String Token string for PC matching and chip rendering. Same NULL / NONE rule as mac_sc.
difficulty Integer Controls which pool the shortcut enters based on the player's difficulty setting. Range to be confirmed: existing examples use 0 to 3.
group String Optional. The pool builder caps any named group at two questions per ten-question set. Only add when genuinely needed, for example a set of related opacity shortcuts.
Difficulty range unconfirmed. This table shows 0 to 3 as seen in existing entries. Confirm the true minimum and maximum before relying on this field for pool balancing.
```

03 ) Canonical Chip Order

```

Regardless of the order tokens appear in the JSON string, chips always render in a fixed order. The token string itself does not need to follow this order, the parser reorders it automatically before display.

PlatformOrder
Mac ⌘ ⌃ ⌥ ⇧ key CMD → CONTROL → OPTION → SHIFT → key
PC Win Ctrl Alt ⇧ key WIN → CTRL → ALT → SHIFT → key
```

04 ) System Component Glossary

Use these names when discussing the system. Each corresponds to a distinct function in the JavaScript.

```
FunctionRoleDescription
NormaliseToken( token ) Token normaliser Converts any accepted synonym to its canonical form, for example OPTION to OPT in Mac fields, or OPT to ALT in PC fields. Called first by everything else so the rest of the system only ever sees canonical tokens.
ParseShortcutString( shortcutString ) String parser Splits a token string on +, runs each token through NormaliseToken, and returns a structured object describing which modifier flags are required and what the key token is. Also splits on | first to separate piped alternatives, parsing each alternative separately.
GetActiveShortcutString( shortcutEntry ) OS selector Takes a shortcut JSON entry object and returns the correct token string for the current OS: entry.mac_sc on Mac, entry.pc_sc on PC. Returns null when the field is the string NULL or NONE, meaning the shortcut does not exist on this platform.
ShortcutMatchesEvent( shortcutString, keyboardEvent ) Match checker Takes a token string and a browser keyboard event. Returns true if the event satisfies the shortcut. Calls ParseShortcutString internally, then checks modifier flags and physical key code against the parsed result.
ShortcutToKeyCodes( shortcutString ) Keyboard lighting Takes a token string and returns the array of browser key code strings that need to be lit on the graphical keyboard display. Used only by the lighting system, not by match checking.
RenderShortcutChips( shortcutString, isLongForm ) Chip renderer Takes a token string and a boolean. When isLongForm is true, used for shortcuts with one or two tokens, renders wide chips with word labels. When false, used for three or more tokens, renders compact chips with symbols only. Canonicalises token order before rendering. Returns a DOM element.
```
